          Multi-Tenant GitOps Architecture Comparison
        

      

      

        
          

            Dimension
            Flux on Agent Substrate (Workflow Actors)
            Shared Multi-Tenant Flux Controller Pods
            One-Off Kubernetes Job Pods per Reconcile
          

        
        
          

            Execution Unit
            1 gVisor Workflow Actor per Tenant Environment (24 actors multiplexed across 3 WorkerPool pods)
            Shared source-controller + kustomize-controller process for all tenants
            Cold container Pod scheduled per Git commit
          

          

            Idle Memory (24 Tenants)
            0 MiB per suspended actor (suspended to DurableDir volume snapshot between turns)
            Always-on controller-runtime informers + Go heaps running 24/7
            0 MiB when idle, high Pod scheduling & image pull churn on wake
          

          

            Git Checkout Cache
            Warm shallow .git persisted in DurableDir (/var/lib/flux); incremental delta fetch only
            Ephemeral tarball artifact download + unpack every reconcile
            Cold full/shallow git clone on every Job execution
          

          

            Kustomize OOM Blast Radius
            Strictly contained to the single tenant's Workflow Actor (ACTOR_STATE_CRASHED + 1-click RevertActor)
            OOMKills the shared kustomize-controller Pod, halting all 24 tenants
            Isolated per Job, but leaves dirty partial state without volume snapshot rollback
          

          

            In-Sandbox Secrets
            Zero secrets inside sandbox; atenet-egress injects actorJwt & ate-secret:// headers outside the sandbox
            Controller Pod mounts Secret volumes or broad ServiceAccount tokens
            Job Pod mounts Secret volumes or ServiceAccount tokens inside container memory
