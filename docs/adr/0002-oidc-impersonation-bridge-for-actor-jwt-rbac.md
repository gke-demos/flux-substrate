# Bridge actorJwt to Kubernetes RBAC via an in-cluster OIDC impersonation proxy

Managed Kubernetes control planes such as GKE cannot directly fetch JWKS keys from an internal cluster-DNS OIDC issuer (`https://idp.ate-system.svc`), while storing per-tenant Kubernetes ServiceAccount tokens in `ate-secret://` would introduce static cluster credentials and forfeit cryptographic actor identity. Instead, `atenet-egress` injects an `actorJwt` on requests to an in-cluster `Identity Bridge` (`https://kube-bridge.flux-substrate.svc`), which verifies the token against `ate-idp-server` and forwards the Kubernetes API call to `kubernetes.default.svc` using `Impersonate-User: ate:actor:<atespace>:<actor>` bound to per-namespace `RoleBinding`s, while Git HTTPS credentials use `ate-secret://k8s.io/...`.
